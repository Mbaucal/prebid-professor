# MBA-216: locked tools for builtin TEST Pages workflows

Base TEST: `c5d8467d9d192eeeb726f60fb864244dfa3c009e`. This candidate changes the two TEST-only delivery/reverification workflows and their existing verification CI. It does not dispatch a workflow, publish to Pages, change `verify-existing.json`, or modify generic staging/production delivery.

## Why retain the existing action

The exact [action definition](https://github.com/cloudflare/wrangler-action/blob/9acf94ace14e7dc412b076f2c5c20b8ce93c79cd/action.yml) and [executed bundle](https://github.com/cloudflare/wrangler-action/blob/9acf94ace14e7dc412b076f2c5c20b8ce93c79cd/dist/index.mjs) were inspected. That commit contains only the definition and bundle; source modules are embedded in the bundle. Its Git blob is `ccab30acedbf9809f60d5e8de0454a730a2a75ff`.

`resolveInstalledVersion` / `installWrangler` (bundle lines 38022–38062) run the package manager's no-install version command at the selected working directory and skip installation when the explicitly requested exact version matches. The npm manager maps this to `npx --no-install wrangler --version`; deployment then uses `npx wrangler` in the same directory. The candidate sets `workingDirectory: tools`, `packageManager: npm` and exact version `4.131.0` after the locked bootstrap and a preflight that independently executes the same version lookup. There is no new generic deployment wrapper or package installation path.

The retained action still emits its structured Pages outputs, handles command failure, and keeps its optional best-effort GitHub deployment/status and job-summary behavior. The caller still reads `deployment-url` and `steps.deploy.outcome`. Claim-before-prepare, private original package checks, actual production-branch exclusion, independent public verification and retry-only reporting remain unchanged. A failed preflight leaves the deploy step skipped; an action failure remains uncertain through the existing `runnerOutcome` contract. Report retries do not invoke the deploy action.

## Authority and prepared inputs

The fixed asset argument changes only to `../.generated/builtin-delivery/dist` for the tools working directory. All dynamic command fields retain the existing restrictive TEST input validation before claim/prepare. The preflight rechecks repository/ref, claimed run/commit, input/receipt/package identity, exact saved delivery layout, file set, bytes and `_headers`, rejecting extra files, symlinks and changed hashes. It checks tools resolution, installed closure and exact version, rejecting missing/nonzero/prerelease/ambiguous output before the action can attempt fallback installation.

Wrangler 4.131.0's installed `src/pages/deploy.ts` code discovers ancestor configuration. The existing root Worker configuration has no `pages_build_output_dir`; `readPagesConfig` rejects it as a Pages config and Pages deploy ignores it, retaining explicit directory/project flags. Preflight rejects unexpected tools configuration, root alternative configurations, Pages functions and root/tools redirect files. In particular a prior Vite build's `.wrangler/deploy/config.json` is refused: the actual deploy job is a fresh checkout/bootstrap/prepare job with no Vite build step.

The same installed CLI's `getUnsupportedDeployDelegateArgs` includes the fixed branch and commit-message arguments; `maybeDelegatePagesToWorkers` immediately declines delegation when these arguments are present. No `--force` flag was added. The target remains Pages, including a project-disappearance failure; no Workers publishing path was introduced.

## Evidence and limits

Local Node 24.19.0: fresh checked-in npm-ci bootstrap, strict3 and App build pass; historical isolation still verifies 16 production package instances and all 66 fixed outputs. The full existing delivery/reverification/publisher/Pages/callback/legacy suite plus new preflight checks passes (152 tests). Checks cover both archive and publisher-script layouts, byte/header changes, extra assets, missing claim, different run, changed receipt, wrong ref, missing/mismatched tools and unexpected configuration. Tests restore temporary mutations; source/runtime/lock inputs remain unchanged.

`verify-pinned-wrangler-action.mjs` first checks the exact bundle Git blob, then runs the actual action with fake local npm/npx binaries and blocked network. Success proves no npm install, the tools working directory and exact argv, structured immutable deployment URL/environment outputs. Command failure proves a failed outcome with no deployment URL. Optional GitHub metadata calls are not invoked in this synthetic test; they are retained unchanged and source-reviewed, not claimed as live API-tested. The existing Pages verification workflow checks out the exact action into a secondary generated directory and executes this test; no deploy credentials are present.

Reproduce after bootstrap and runtime/Test-workspace preparation: `TZ=UTC node --experimental-strip-types --test tests/runtime/builtin-pages-preflight.test.mjs` and `node scripts/verify-pinned-wrangler-action.mjs /path/to/exact-action/dist/index.mjs`. Run the preflight test before a Vite build, as the deployment job does; an unexpected generated Wrangler redirect is intentionally blocked. The existing Pages CI runs all original suites plus these checks on Node 22.23.3. Candidate CI and any future authorized hosted Pages delivery are separate evidence. No new hosted acceptance is claimed or requested; MBA-52 remains open for generic deployment/main/default/historical scope.

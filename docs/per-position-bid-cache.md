# Bid cache per ad position

Every site can save bid caching. The site default is under Config → Demand → Prebid ("Reuse valid, unused bids" and a maximum bid age of 1–300 seconds). Each eligible position has three choices under Config → Ad units → Bid cache:

- **Use site setting**: inherit the current default in Config → Demand → Prebid.
- **On**: let valid, unused bids from earlier auctions for this position compete with fresh bids.
- **Off**: use only bids from the current auction for this position.

Each refresh still starts a fresh auction. A higher fresh CPM can win on any refresh, including the third. Turning cache off does not prevent the GAM request when the fresh auction returns no bids.

Saving changes the configuration for the next package only. It does not modify saved packages, existing ZIPs or an active publisher deployment. Removing an override restores inheritance; changing the site default preserves explicit overrides. Disabling Prebid keeps the choices saved but inactive.

## Which positions can reuse bids

A position is eligible when its ad unit is enabled, in the ATF or BTF group, and Banner. The rule is `bidCacheEligibleCodes` in `shared/bid-cache/eligibility.mjs`, shared by the admin API and the runtime. These positions always use the current auction and are never dropped: Draft and disabled units, video and native units, the TakeOver ad position and its Interstitial fallback (or the legacy TakeOver code), and Outstream positions. Ad units shows a Bid cache button only for eligible positions, and re-reads the list after a unit, its Formats or its display changes.

The API (`PUT /api/publishers/:id/prebid-mode`) checks, in this order:

1. the shape: a boolean, an age of 1–300 seconds, and at most 500 overrides, each a valid GAM ad unit code with a boolean (422);
2. the form revision, so a stale form never overwrites another change (409);
3. that every new or changed override names one of the site's eligible positions (422, for example "Choose bid caching on or off for a supported ad position. Sticky is not an enabled ATF or BTF banner position on this site. Reload to see the current positions.").

An override saved earlier for a unit that later became ineligible (renamed, deleted, disabled, moved to Draft, made Outstream or TakeOver) is kept when it is sent back unchanged, so it never blocks an unrelated save. It is not applied: a package generated with 3.23.0 records it as a warning in its manifest and README (under "Saved settings not applied in this package"). Demand → Prebid lists it as "Not applied" with a **Remove unused overrides** action; removing an override is always allowed.

## Which scripts apply it

Built-in packages apply bid caching only when the site's saved script version has the `bid-cache` capability. 3.23.0 is the first such version, and a site uses it only after it is explicitly selected in Script setup. Demand → Prebid, the position dialog and Generate name the same versions, read from the release registry: those that apply bid caching together with the site's other saved options (bidder accounts, bidder rules), at most two of them, the smallest step (the version with the fewest capabilities, the newest patch on a tie) and the newest, leaving out versions with a runtime notice. Never "or later". On TEST, with the releases up to 3.24.0, that is 3.24.0 (Preview) alone (main, with the releases up to 3.26.0, names 3.24.0 (Preview) or 3.26.0 (Preview)). The panels say which case applies:

- capable version selected: "Applies to new packages generated with the selected script." (the position dialog: "Applies to the next package generated with the selected script.");
- another version, or no built-in version, with saved settings that would reuse bids (the site default on, or a position override on): "Select script 3.24.0 (Preview) in Script setup to apply bid caching. Your setting is saved." (with two versions: "Select script 3.24.0 (Preview) or 3.26.0 (Preview) …"). While the form has unsaved changes, the last sentence is left out;
- another version and nothing saved that would reuse bids: "Bid caching needs script 3.24.0 (Preview)." The position dialog says "Applies to the next package generated with script 3.24.0 (Preview). Select that version in Script setup to use it." (with two versions: "… with script 3.24.0 (Preview) or 3.26.0 (Preview). Select one of these versions in Script setup to use it.").

With an earlier version, Prebid on and saved settings that would reuse bids, Generate stops with 409 "Bid caching needs a compatible script version. Select 3.24.0 (Preview) in Script setup and save; your bid cache settings are kept. This version combines bid caching with bidder accounts, bidder rules and the current native activity and floor checks. To keep this script version instead, turn bid caching off in Config → Demand → Prebid, remove unused overrides there, and set positions that are On to Use site setting under Config → Ad units → Bid cache." With two versions it reads "Select 3.24.0 (Preview) or 3.26.0 (Preview) … Both versions combine …". Releases → Generate shows that message above Script setup. Saved settings that would reuse bids are never silently ignored. Overrides that are all Off need no capable version: without bid caching every position already uses only its current auction. With Prebid off, Generate continues GAM-only and the settings stay saved. The older legacy generator and preview bundle routes keep refusing saved cache settings that would reuse bids.

The browser behavior of the capable runtime (consent, size, age, TTL and submitted-bid rules) is documented with that runtime release.

## TEST site workspace

The TEST workspace (`/site-workspace`) applies the same rules to the TEST site through the same shared service. **Bid caching** opens the production Demand → Prebid panel for the TEST site, with **Bid cache by position** below it: one button for each eligible position, opening the production position dialog. The TEST Worker routes `GET` and `PUT /api/publishers/test-site/prebid-mode` (and no other site) to the shared `getPrebidMode` and `updatePrebidMode` after the TEST host, authentication, same-origin and schema checks; a query is 400, other methods 405 and a field other than `enabled`, `revision` and `bidCache` 422. Prebid on/off, its build and the TEST draft marker stay with **Prebid and bidders**: the mode choice is read-only on this page, and a save that would change it is refused with 409 "Turn Prebid on or off in Prebid and bidders. Here you can change bid caching only." without a write. A form loaded before Prebid was turned on or off elsewhere gets the shared 409 "Prebid settings changed. Reload before saving." instead. The TEST home page links **Bid caching** next to **Prebid and bidders**.

The runtime catalog checks every descriptor before it builds: `buildArtifactCandidate` calls `requireSupportedCacheGenerator(config, descriptor, bidders)` for every engine and route (the saved bidder rows only word the refusal), so saved settings that would reuse bids need the `bid-cache` capability on any path. The site package state reports the same check, and **Generate and releases** shows it above Script setup. Its text names this workspace's pages instead of Config: "… To keep this script version instead, open Bid caching, turn off Reuse valid, unused bids, remove unused overrides there, and set positions that are On to Use site setting under Bid cache by position." The rest of the sentence, the versions it names and the 409 status are the shared ones.

The older Generate on the TEST home page (`/test-api/generate` and `/test-api/save`) gives the same reason: `/test-api/status` reports it before Generate, which stays disabled, and the route refuses with the guard's own status and message (409) instead of a storage error. A guard refusal with its own 4xx status (bid caching, bidder rules) is passed on the same way.

Of the TEST script versions, only 3.24.0 Preview has both bid caching and bidder rules; the TEST messages below name the versions that apply both from the registry, by the same rule as the panels. With bidder rules on and a script without bid caching, the bid cache reason says so: "This script cannot combine bid caching and bidder rules. To use both, select 3.24.0 Preview in Script setup, allow Preview scripts, and save. To keep this script version instead, turn bid caching off: …" Script setup refuses 3.23.0 with bidder rules on (422): "Script 3.23.0 has bid caching but cannot apply enabled bidder rules. To use both, select 3.24.0 Preview in Script setup, allow Preview scripts, and save. To keep 3.23.0 instead, turn off bidder rules in Bidder rules. Your saved settings are kept." The TEST runtime catalog checks this before the shared script version guidance and the shared bidder rules guard, whose "3.22.0 or later" text is in the frozen 3.22.0 closure. For other scripts without bidder rules or bidder accounts, the shared guidance names at most two versions that apply every saved option (the smallest step and the newest), for example "Script 3.21.2 cannot apply enabled bidder rules. Select 3.22.2 (Preview) or 3.24.0 (Preview) in Script setup and save, or turn off bidder rules. …", and only 3.24.0 (Preview) when bid caching is saved. When the selected script cannot apply the saved bid caching either, the message does not offer turning off bidder rules, because Generate would still refuse that script for bid caching. The Bidder rules page and the account note in Prebid and bidders name the versions the server derives the same way. The older `/test-api/runtime-selection` page and the `version` action of `/test-api/site-runtime` show these messages as written; other configuration refusals there keep the shared generic message.

## Named scripts (TEST copy)

The TEST named-script copy (`/named-scripts`, site `test-named-script`; its page points to Site workspace → Bid caching for the TEST site) reuses the Scripts and A/B tests library with the reviewed Tanjug inventory. Its named scripts use the same saved settings for their 19 reviewed positions with the existing cache lifecycle and pinned Prebid 11.34.0. An override for any other position stops a new named script with 409 instead of dropping it. Existing named scripts and A/B ZIPs keep their exact bytes and settings. Named scripts do not use the runtime selected in Script setup. On TEST pages the copy names "Scripts and A/B tests" without the production "Releases →" prefix.

## Implementation and verification

`prebidBidCache = {enabled, maxBidAgeSeconds, positionOverrides?}` in the site configuration is unchanged. Overrides are stored in code-unit order. `GET /prebid-mode` returns `bidCachePositions` (the eligible codes), `bidCacheRuntimeVersion`, `selectedRuntime` (only when the runtime catalog still verifies the saved pin), `runtimeSupportsBidCache`, `namedScriptLibrary` and `namedScriptPositions` (the 19 reviewed named-script positions on Tanjug, else empty). The last two only choose the named-script sentence: the position dialog says new named scripts use the override only for those positions, and otherwise that an override there stops new named scripts until it is set to Use site setting. They never change what can be saved.

- `tests/runtime/prebid-mode-bid-cache.test.mjs`: a synthetic `example.invalid` site saves cache and its own overrides; Tanjug codes, ineligible positions and malformed overrides are refused without writes; stale revisions get 409; kept overrides never block unrelated saves; the payload for 3.21.2, a changed pin, any catalog descriptor with the capability and the registered 3.23.0; Tanjug gets the same cache fields and its named-script positions.
- `tests/runtime/bid-cache-test-workspace.test.mjs`: the TEST site through the TEST Worker. Prebid off in an empty copy, a refused Prebid toggle without a write, a save with the actor recorded after Prebid is turned on in the TEST editor, a foreign code (422), a stale revision (409), the route boundaries (401, 403, 400, 405, 422), a generated 3.23.0 package whose `config.json` carries the saved settings, and with 3.21.2 the blocked state and 409 with the TEST reason until bid caching is turned off.
- `tests/runtime/bid-cache-test-workspace.test.mjs` also covers the older `/test-api/generate` (409 with the TEST reason, `/test-api/status` reports it, and Generate works with 3.23.0), a stale form after Prebid was turned off in the TEST Prebid editor (reload message, no write), and bidder rules with bid caching (the bidder rules variant of the reason on 3.22.0, Script setup refusing 3.23.0 with and without bid caching, and the plain reason once bidder rules are off). `tests/runtime/bidder-rules-catalog.test.mjs` expects the combined reason from 3.23.0 and the shared one from every other runtime without bidder rules.
- `tests/runtime/bid-cache-test-wording.test.mjs`: the home page link to Bid caching, the named-script page sentence, the Bidder rules copy and the account note in Prebid and bidders, which take their script versions from the server.
- `tests/runtime/named-script-test.test.mjs`: the TEST named-script copy keeps its own route, and the TEST site route refuses a Prebid toggle.
- `scripts/verify-bid-cache-settings-ui.py`: real React panels and the compiled production Worker on the synthetic site (TEST fixture: `scripts/bid-cache-settings-browser-fixture.mjs`) at 1280 and 390 px: loading, saving, a 409 stale form and reload, a 422 position that stopped being eligible and reload, removing an unused override, Prebid off, and the copy once the saved selection is the registered 3.23.0. It also opens Releases → Generate on a site with 3.21.2 selected and bid caching saved: the 409 reason with both ways out is shown above Script setup at both widths, and turning caching off or selecting 3.23.0 unblocks Generate.
- `scripts/verify-test-bid-cache-ui.py`: the TEST site workspace at 1280 and 390 px. The named-script page and Bidder rules wording, Bid caching opened from the TEST home page with the mode read-only, a saved default and position override, Generate blocked with the TEST reason above Script setup and on the TEST home page (disabled, and 409 from its route), then 3.23.0 selected and a downloaded package with the saved settings.

No external live auctions are used by these tests.
